## 개발용 상세 변경 내역 (App Store 비공개)

발표 목록 (build 3)
- fix: 장표 0장 발표가 목록에 잠깐 나타났다 사라지는 문제
  - 원인: 카메라·사진 가져오기를 **시작하는 시점**에 `Store.addPresentation`으로
    발표를 만들어 `presentations`에 넣고 저장까지 했다. fullScreenCover가 올라오기 전/
    내려가는 동안 그 "0장" 행이 목록에 그대로 보이고, 한 장도 안 찍고 닫으면
    `deletePresentation`으로 지워져 나타났다 사라지는 깜빡임이 됐다.
  - 해결: **초안(draft) 발표** 도입. `beginDraftPresentation`은 `presentations`에 넣지도,
    파일로 저장하지도 않는다. 첫 장표가 실제로 저장될 때 `promoteDraft`로 목록에 올리고,
    안 찍고 닫으면 `discardDraft`로 버린다. 촬영 후 닫을 때는 목록 승격과 상세 화면 이동이
    같은 갱신에 일어나 0장 행이 보이지 않는다.
  - 부수 효과: 앱이 촬영 중에 강제 종료돼도 초안은 저장된 적이 없어 찌꺼기 발표가 안 남는다.
- fix: 사용자가 "빈 발표 만들기"로 만든 발표가 2분 뒤 저절로 사라지던 문제
  - 원인: 위 깜빡임을 뒤에서 치우려고 두었던 `removeEmptyPresentations(grace: 120)`이
    scenePhase `.active`와 목록 복귀 때 돌면서, 일부러 만든 빈 발표까지 지웠다.
  - 해결: 초안 방식이 원인을 없앴으므로 이 자동 정리와 호출부를 제거했다.

피드백 알림 (개발자 인박스)
- fix: "새 피드백 알림"을 CloudKit 구독(CKQuerySubscription) → **로컬 알림(BGAppRefreshTask + UNUserNotification)** 방식으로 전환
  - 원인: public DB의 쿼리 구독은 Production 컨테이너에서 생성이 거부됨
    ("attempting to create a subscription in a production container") + `status` 필드 미배포로 저장 실패
  - 해결: 서버 푸시 대신 백그라운드 새로고침으로 새 피드백을 주기적으로 조회해 로컬 알림 발송,
    앱을 열 때(포그라운드)에도 확인. 켠 시점 이후 접수분만 알림(밀린 피드백 폭탄 방지),
    인박스 진입 시 '봄' 처리로 중복 알림 방지
- change: 기존 구독 기반 API는 deprecated 처리(개발 환경 한정)

인프라 / 빌드
- build: LeeoKit 원격 SPM 2.4.0 → **2.5.0** (로컬 알림 API 추가분 반영)
- chore: Info.plist에 `UIBackgroundModes=[fetch]` + `BGTaskSchedulerPermittedIdentifiers`(`com.leeokit.feedback.refresh`) 추가
- chore: SlideSnapApp에 `.backgroundTask(.appRefresh…)` 핸들러 + 포그라운드 확인 배선
- chore: 버전 1.0.3 → 1.0.4 (build 2 → 3)

## ⚠️ 배포 전 체크

- 새 피드백 로컬 알림은 인박스 조회에 의존하므로, CloudKit Dashboard(FeedbackHub)에서 admin 역할 **Read 권한**이 설정돼 있어야 동작 (기존 1.0.3 요건과 동일)
- 로컬 알림 방식이라 **CloudKit 구독/스키마 추가 배포는 불필요** — `Feedback.status` 필드 배포 없이도 알림 동작
- 백그라운드 새로고침은 iOS가 사용 패턴에 따라 스케줄 → 실시간 아님(관리자용 편의 기능)
